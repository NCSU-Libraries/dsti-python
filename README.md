A hands-on introduction to Python from NC State University Libraries' Data Science Services, first taught at the
*Data Science Training Intensive*. Attendees install Python and JupyterLab on their own laptop with
[uv](https://docs.astral.sh/uv/) (or conda, if they already use it), then work there: variables, data types, lists and
dictionaries, operators, `if`, `for`, methods, and a function of their own. Google Colab is the backup when an install
gets stuck.

**Workshop site:** <https://ncsu-libraries.github.io/dsti-python/>

To work on your laptop, follow the site's [Setup page](https://ncsu-libraries.github.io/dsti-python/setup.html): it
downloads the notebook and opens it in JupyterLab. In Colab, click **Copy to Drive** so your changes are saved to your
own Google Drive.

The notebooks condense the Basics and Loops and Functions workshops from
[Getting Started with Python](https://github.com/NCSU-Libraries/getting-started-with-python). The full workshops cover
everything skipped here: dates and times, type conversion, `while` loops, and reading and writing files.

## What's here

| Path | What it is |
| --- | --- |
| `notebooks/` | The session's learner and filled notebooks, generated by `tools/build_notebooks.py`, and the follow-along activities' notebooks, generated by `tools/build_activities.py` |
| `data/` | The activities' data files, served from the site for download |
| `site/` | The Quarto website: start page, setup guide, cheat sheet, and the slide deck (`site/slides/`) |
| `tools/` | The notebook builder, the post-render step that copies the notebooks into the site, a link checker, and a screenshot script |

## Build it locally

You need [Quarto](https://quarto.org) 1.10 or later. RStudio ships one at
`/Applications/RStudio.app/Contents/Resources/app/quarto/bin/quarto`.

```bash
quarto render site                   # builds site/_site, including the deck; post-render copies notebooks/ into it
quarto preview site                  # or serve it locally while editing
python3 tools/check_links.py [--web] # checks every link and image in site/_site; --web also requests external URLs
```

## Rebuild the notebooks

The notebooks are built from a pinned commit (`9b288fa`) of
[getting-started-with-python](https://github.com/NCSU-Libraries/getting-started-with-python). With that repository
checked out locally:

```bash
python3 tools/build_notebooks.py --src ~/Desktop/getting-started-with-python
```

Change the notebooks by editing the manifest in `tools/build_notebooks.py` and running it again. Hand edits to the
`.ipynb` files are overwritten on the next build.

## Publishing

Pushing to `main` runs `.github/workflows/deploy-pages.yml`, which renders the site and deploys it to GitHub Pages. Set
**Settings → Pages → Source** to **GitHub Actions** *before* the first push, or the first deploy fails; if it did,
re-run the workflow from the **Actions** tab. Changes to `notebooks/` redeploy too, because the site serves the
notebooks for download. The Colab links work once the repository is public on GitHub.

If the site moves to a different GitHub owner or repo name, search for `ncsu-libraries.github.io` and
`NCSU-Libraries/dsti-python` and change both, then point the go link in `site/_variables.yml` at the new
address and regenerate its QR code (`site/images/qr-session.svg`).
